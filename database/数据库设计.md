# VitaeLens 数据库设计文档

本文档依据 [`database/sql/schema.sql`](sql/schema.sql) 整理，描述当前已落地的 MySQL 表结构、字段含义、索引与表间关系。业务语义以仓库 [`AGENTS.md`](../AGENTS.md) 与后端实现为准。

## 1. 概述

### 1.1 数据库选型

| 项 | 说明 |
|----|------|
| 引擎 | MySQL 8.0 / InnoDB |
| 字符集 | `utf8mb4` |
| 排序规则 | `utf8mb4_unicode_ci` |
| 建表脚本 | `database/sql/schema.sql` |
| 部署初始化 | `deploy/mysql-init` 挂载上述脚本 |

### 1.2 设计目标

- 支撑用户鉴权、简历与岗位 JD 管理、异步简历分析、模拟面试与 AI 调用日志。
- 以 `user_id` 做数据隔离；业务侧查询必须带当前登录用户条件。
- 分析任务通过 `input_hash` 支持结果复用（配合 Redis 缓存）。
- AI 结构化结果以 JSON 字段落库，避免把未校验的原始文本当作正式结果。

### 1.3 通用约定

| 约定 | 说明 |
|------|------|
| 主键 | 各业务表使用 `BIGINT AUTO_INCREMENT` |
| 时间字段 | `created_at` / `updated_at`，默认值与自动更新由数据库维护；业务实体由 MyBatis-Plus 填充 |
| 逻辑删除 | 业务主表含 `deleted`（`TINYINT`，0 未删除 / 1 已删除），对应 `@TableLogic` |
| 外键约束 | 脚本**未声明**数据库级 `FOREIGN KEY`；关联由应用层保证，便于异步任务与逻辑删除 |
| 敏感字段 | `password_hash` 存 BCrypt 哈希；`file_path` 仅服务端使用，不返回前端 |

## 2. 表清单

| 表名 | 说明 |
|------|------|
| `user` | 用户账号与角色 |
| `resume` | 简历文件元信息与解析文本 |
| `job_description` | 目标岗位 JD |
| `analysis_task` | 简历分析异步任务与结果 |
| `interview_session` | 模拟面试场次 |
| `interview_question` | 面试题、用户回答与 AI 反馈 |
| `ai_call_log` | AI 调用耗时与成功/失败日志 |

## 3. ER 关系

```text
user 1 ─── * resume
user 1 ─── * job_description
user 1 ─── * analysis_task
user 1 ─── * interview_session

resume 1 ─── * analysis_task
job_description 1 ─── * analysis_task

analysis_task 1 ─── * interview_session
analysis_task 1 ─── * ai_call_log   （逻辑关联：ai_call_log.task_id）

interview_session 1 ─── * interview_question
```

关系说明：

- 一次分析任务绑定一份简历（`resume_id`）与一份岗位 JD（`jd_id`）。
- 一次模拟面试场次绑定一次成功（或已存在）的分析任务（`analysis_task_id`）。
- `ai_call_log.task_id` 可为空；当前分析路径会写入分析任务 ID，面试相关调用尚未统一落库。

## 4. 表结构详情

### 4.1 `user` — 用户表

存储注册用户与管理员账号。密码仅存哈希；角色区分普通用户与管理员。

| 字段 | 类型 | 空 | 默认值 | 说明 |
|------|------|----|--------|------|
| `id` | BIGINT | N | AUTO_INCREMENT | 主键 |
| `username` | VARCHAR(50) | N | — | 用户名，唯一 |
| `password_hash` | VARCHAR(255) | N | — | BCrypt 密码哈希 |
| `email` | VARCHAR(100) | Y | NULL | 邮箱，唯一（允许多个 NULL，取决于 MySQL 唯一索引语义） |
| `role` | ENUM('user','admin') | N | `'user'` | 角色 |
| `created_at` | DATETIME | N | CURRENT_TIMESTAMP | 创建时间 |
| `updated_at` | DATETIME | N | CURRENT_TIMESTAMP ON UPDATE | 更新时间 |
| `deleted` | TINYINT | N | 0 | 逻辑删除 |

索引：

| 名称 | 类型 | 列 |
|------|------|----|
| PRIMARY | 主键 | `id` |
| `uk_username` | 唯一 | `username` |
| `uk_email` | 唯一 | `email` |

### 4.2 `resume` — 简历表

保存上传文件的展示名、服务端存储路径及解析后的纯文本。解析失败时 `parsed_text` 可为空。

| 字段 | 类型 | 空 | 默认值 | 说明 |
|------|------|----|--------|------|
| `id` | BIGINT | N | AUTO_INCREMENT | 主键 |
| `user_id` | BIGINT | N | — | 所属用户 |
| `file_name` | VARCHAR(255) | N | — | 原始/展示文件名 |
| `file_path` | VARCHAR(500) | N | — | 服务端存储路径（不暴露给前端） |
| `parsed_text` | TEXT | Y | NULL | PDF/DOCX 解析文本 |
| `created_at` | DATETIME | N | CURRENT_TIMESTAMP | 创建时间 |
| `updated_at` | DATETIME | N | CURRENT_TIMESTAMP ON UPDATE | 更新时间 |
| `deleted` | TINYINT | N | 0 | 逻辑删除 |

索引：

| 名称 | 类型 | 列 |
|------|------|----|
| PRIMARY | 主键 | `id` |
| `idx_user_id` | 普通 | `user_id` |

### 4.3 `job_description` — 岗位 JD 表

用户创建的目标岗位描述。当前 schema **不含**公司名称字段。

| 字段 | 类型 | 空 | 默认值 | 说明 |

| `user_id` | BIGINT | N | — | 所属用户 |
| `title` | VARCHAR(100) | N | — | 岗位名称 |
| `content` | TEXT | N | — | 岗位描述全文 |
| `created_at` | DATETIME | N | CURRENT_TIMESTAMP | 创建时间 |
| `updated_at` | DATETIME | N | CURRENT_TIMESTAMP ON UPDATE | 更新时间 |
| `deleted` | TINYINT | N | 0 | 逻辑删除 |

索引：

| 名称 | 类型 | 列 |
|------|------|----|
| PRIMARY | 主键 | `id` |
| `idx_user_id` | 普通 | `user_id` |

### 4.4 `analysis_task` — 分析任务表

核心业务表。创建时写入 `PENDING`，异步执行中为 `RUNNING`，结束后为 `SUCCESS` 或 `FAILED`。

| 字段 | 类型 | 空 | 默认值 | 说明 |
|------|------|----|--------|------|
| `id` | BIGINT | N | AUTO_INCREMENT | 主键 / taskId |
| `user_id` | BIGINT | N | — | 所属用户 |
| `resume_id` | BIGINT | N | — | 关联简历 |
| `jd_id` | BIGINT | N | — | 关联岗位 JD |
| `input_hash` | VARCHAR(64) | Y | NULL | 输入指纹（简历文本 + JD 内容的 MD5），用于缓存复用 |
| `status` | VARCHAR(20) | N | `'PENDING'` | 任务状态 |
| `score` | INT | Y | NULL | 总分（来自 AI `overallScore`） |
| `result_json` | JSON | Y | NULL | 结构化分析结果 |
| `error_message` | VARCHAR(1000) | Y | NULL | 失败原因 |
| `retry_count` | INT | N | 0 | 失败计数；当前无自动多轮重试 |
| `started_at` | DATETIME | Y | NULL | 开始执行时间 |
| `finished_at` | DATETIME | Y | NULL | 结束时间 |
| `created_at` | DATETIME | N | CURRENT_TIMESTAMP | 创建时间 |
| `updated_at` | DATETIME | N | CURRENT_TIMESTAMP ON UPDATE | 更新时间 |
| `deleted` | TINYINT | N | 0 | 逻辑删除 |

索引：

| 名称 | 类型 | 列 | 用途 |
|------|------|----|------|
| PRIMARY | 主键 | `id` | 按 taskId 查询 |
| `idx_user_id` | 普通 | `user_id` | 历史任务列表 |
| `idx_input_hash` | 普通 | `input_hash` | 相同输入命中已有 SUCCESS 任务 |
| `idx_status` | 普通 | `status` | 按状态筛选（预留） |

#### 状态机

```text
PENDING -> RUNNING -> SUCCESS
PENDING -> RUNNING -> FAILED
```

- Redis 命中时可能直接返回 SUCCESS 结果，不一定新建任务记录。
- 数据库命中相同 `input_hash` 的 SUCCESS 任务时，回填 Redis 并返回该任务。
- `FAILED` 当前不会自动回到 `RUNNING`（无手动重试接口）。

#### `input_hash` 计算（业务约定）

```text
MD5(resume.parsed_text + "|" + job_description.content)
```

#### `result_json` 推荐结构

与 AI 输出校验一致，至少包含 `overallScore`、`dimensionScores`：

```json
{
  "overallScore": 78,
  "dimensionScores": {
    "technicalMatch": 80,
    "projectExperience": 75,
    "expressionQuality": 70,
    "jobMatch": 85
  },
  "strengths": ["..."],
  "weaknesses": ["..."],
  "skillGaps": ["Redis", "消息队列"],
  "rewriteSuggestions": [
    {
      "original": "...",
      "suggested": "...",
      "reason": "..."
    }
  ],
  "interviewFocus": ["..."]
}
```

`feedback_json` 由业务解析后写入，通常包含评分、问题诊断与改进建议等字段（具体以面试评价 Prompt / 响应 DTO 为准）。

### 4.7 `ai_call_log` — AI 调用日志表

记录大模型调用耗时与状态。该表**无** `updated_at` / `deleted`，为追加型日志。

| 字段 | 类型 | 空 | 默认值 | 说明 |
|------|------|----|--------|------|
| `id` | BIGINT | N | AUTO_INCREMENT | 主键 |
| `task_id` | BIGINT | Y | NULL | 关联分析任务 ID（可空） |
| `module` | VARCHAR(50) | N | — | 调用模块，见下表 |
| `prompt_tokens` | INT | Y | NULL | Prompt token（预留，业务侧尚未完整写入） |
| `completion_tokens` | INT | Y | NULL | Completion token（预留） |
| `total_tokens` | INT | Y | NULL | 总 token（预留） |
| `duration_ms` | INT | Y | NULL | 调用耗时（毫秒） |
| `status` | VARCHAR(20) | N | — | `SUCCESS` / `FAILED` |
| `error_message` | VARCHAR(1000) | Y | NULL | 失败信息 |
| `created_at` | DATETIME | N | CURRENT_TIMESTAMP | 记录时间 |

索引：

| 名称 | 类型 | 列 |
|------|------|----|
| PRIMARY | 主键 | `id` |
| `idx_task_id` | 普通 | `task_id` |

`module` 约定值：

| 值 | 含义 |
|----|------|
| `resume_analysis` | 简历分析 |
| `interview_question` | 面试出题 |
| `answer_feedback` | 回答评价 |

当前实现：分析任务路径会写入本表（含耗时与成功/失败）；面试相关 AI 调用暂未统一写入。

## 5. 与 Redis 的配合

MySQL 持久化权威数据；Redis 不替代下列表，仅作加速与防护：

| Redis Key | 对应库表字段 / 场景 |
|-----------|---------------------|
| `analysis:result:{inputHash}` | 与 `analysis_task.input_hash` / `result_json` 对应，TTL 7 天 |
| `rate_limit:{identifier}:{METHOD:URI}` | 无对应业务表，纯限流计数 |

缓存命中顺序（业务层）：Redis → 数据库相同 `input_hash` 的 SUCCESS 任务 → 新建 PENDING 任务。

## 6. 数据隔离与安全约束

- 所有业务查询必须带当前登录用户的 `user_id`（或经 session / task 归属校验），禁止信任前端传入的 `userId`。
- 删除简历时删除（逻辑删除）库记录，并尽量删除本地文件；`file_path` 不得出现在 API 响应中。
- 禁止在日志中打印完整 `parsed_text`、明文密码、JWT 全文、AI API Key。
- `result_json` / `feedback_json` 入库前须经结构化解析与关键字段校验。

## 7. 初始化与变更

1. 本地或空库执行：`database/sql/schema.sql`。
2. Docker Compose 部署时，由 `deploy/mysql-init` 在 MySQL 首次启动时自动执行。
3. 变更表结构时：先更新 `schema.sql`，再同步 Entity / Mapper，并在本文件补充字段与索引说明。
